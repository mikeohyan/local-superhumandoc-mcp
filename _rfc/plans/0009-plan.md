**symbol**. This plan carries out the adoption and records what was verified.

## Judgement calls made during execution

These went beyond a mechanical repoint. Each is cheap to reverse now and
expensive later, which is why they are listed rather than buried in a diff.

**`api-pin` was renamed to `upstream-api`.** "Pin" is the decision, not the
subject. A future RFC that stops pinning — tracking upstream, or generating a
client from the live spec — could not reuse `api-pin` without the name lying,
which is the exact failure the mechanism exists to prevent. The name was also
already under-inclusive for its own RFC: RFC 0008 decides the version pin *and*
the advisory-rate-limit stance, and rate-limit policy is not pinning.

**`.gitignore` was re-attributed from `upstream-api` to `config-resolution`.**
It previously credited the "token lives only in `.env`" requirement to RFC 0008,
which merely restates it and defers: "read from `.env` per RFC 0006". RFC 0006 is
where the requirement is argued. The wording was also tightened to "never appear
in a committed file", because RFC 0006 loads with `override=False`, so a real
environment variable legitimately outranks the file — "only in `.env`" overstated
it.

**`tool-surface` was kept** despite covering both the tool surface and the
destructive-operation gate. The gate operates at registration time and so is
literally a fact about which tools exist. If a later RFC revises only the safety
policy, splitting `write-safety` off is a bounded change.

**The `rfc` skill picked up two unrelated fixes** while it was open: "Proposed
and Accepted. Decided, not yet shipped" contradicted itself and now reads
"decided or awaiting decision"; and the supersede snippet used `0003-old-slug` as
a placeholder, colliding with a live RFC number, now `NNNN-old-slug`. These
belong in their own commit.

## Defects found by review and fixed before freeze

RFC 0009's body carried four factual errors, all verified against `git show`:

- It claimed six citations *inside other RFCs* were repaired during RFC 0008's
  supersession. Zero were — `651cf58` touches no RFC body. The claim was
  load-bearing, since it was the evidence for "no supersession creates work in an
  accepted RFC".
- It said four references sat outside `_rfc/`; there were five. The omitted file
  was `.gitignore` — the same omission the RFC elsewhere indicts.
- "Ten places" was not reachable from the record; the count is now stated as
  something checkable rather than as a number.
- It declared `docs/validation/` frozen, which reverses `evidence-location`
  ("files under `docs/` are mutable and unversioned") without superseding it.
  Nothing under `docs/` is exempt now.

It also enumerated the living-document set in three places, inconsistently, in a
document arguing that enumeration inside a frozen record is the failure mode.
Rule 1 now states a criterion and defers the set to the audit command.
