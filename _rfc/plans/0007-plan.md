# Implementation plan — RFC 0007 (packaging and distribution)

Plan for shipping RFC 0007, which is **Accepted** as of 2026-09-04. This is
"Wave 1": the package skeleton and its plumbing, and nothing else.

A plan is the one living document that may cite an RFC by number, because it is
named after the single RFC it implements and is `git rm`'d when that RFC reaches
Implemented.

## Scope

**Ships:** the package, its build, its entry point, its server factory, and its
test harness — an empty but real MCP server that starts, speaks stdio, and lists
zero tools.

**Does not ship, deliberately:**

- The seventeen tools — RFC 0005 (`tool-surface`).
- `.env` resolution and the `SHDOC_*` variables — RFC 0006 (`config-resolution`).
- The rate-limit throttle and API constants — RFC 0008 (`upstream-api`).
- Any Superhuman Docs HTTP call at all. Wave 1 makes no network request to the
  vendor.

**Explicitly out of bounds for this wave:** no git tag, no push to `origin`.
The owner has withheld that. RFC 0007's rule is that a published tag is never
moved, so tagging is a one-way act and is a separate, explicit decision.

## What the build spike already settled

Do not re-derive these. Evidence is at
`docs/validation/2026-09-04-packaging-build-validation.md` and
`docs/reference/mcp-sdk-v2-api-surface.md`.

- `mcp==2.1.1`, `httpx2==2.12.0`, `python-dotenv==1.2.3` resolve together;
  classic `httpx` is absent.
- `from mcp.server import MCPServer`. Transport goes to `run()`, never the
  constructor: `server.run("stdio")`.
- `ToolError` is importable **only** as
  `from mcp.server.mcpserver.exceptions import ToolError`.
- `Client(server, raise_exceptions=True)` does **not** re-raise tool-body
  exceptions. Assert on `CallToolResult.is_error` and `.content`.
- The `[tool.hatch.build.targets.wheel] packages` line is not strictly required
  — hatchling auto-discovers `src/superhumandoc_mcp` — but RFC 0007 keeps it
  explicit, so include it.
- Real stdio client path, for end-to-end tests:
  `mcp.client.stdio.StdioServerParameters` + `stdio_client`, then
  `mcp.client.session.ClientSession`.

## Steps

### 1. Package skeleton

- [ ] `pyproject.toml` at the repository root, matching RFC 0007's Decision
      block exactly: name and console script both `superhumandoc-mcp`,
      `requires-python = ">=3.11"`, dependencies `mcp>=2.1.1,<3`,
      `httpx2>=2.5.0`, `python-dotenv>=1.0`, hatchling build backend, and the
      explicit `packages = ["src/superhumandoc_mcp"]`.
- [ ] `src/superhumandoc_mcp/__init__.py`.
- [ ] `src/superhumandoc_mcp/server.py` exposing a **factory**,
      `build_server() -> MCPServer`. Registration happens inside it, at build
      time, before `run()`. RFC 0005's destructive-tool gating depends on this
      and on nothing dynamic at request time. It registers no tools yet.
- [ ] `src/superhumandoc_mcp/__main__.py` with `main()` calling
      `build_server().run("stdio")`.
- [ ] `uv lock`, and commit `uv.lock` — `.gitignore` says it is intentionally
      tracked, for reproducible builds.

### 2. Test harness

- [ ] In-process test using `mcp.Client(build_server())` that connects and
      asserts `list_tools()` returns empty. This is the wave's acceptance test.
- [ ] A test asserting the error convention on a deliberately-registered
      throwaway tool: a `ToolError` message reaches the client in
      `content`, and a bare exception is redacted to
      `Error executing tool <name>`. Assert on `CallToolResult`, never on a
      raised exception.
- [ ] Scaffold for the REST layer's tests against a **mocked `httpx2`
      transport** — no live calls. Nothing to test against yet, so this is
      structure plus one self-check that the mock intercepts, not coverage.
- [ ] Wire whatever test runner the project adopts into `pyproject.toml`. Note
      that choosing a test runner is a decision with no code, which normally
      wants an RFC; if `pytest` is added as a dev dependency, flag it rather
      than treating it as settled.

### 3. Local verification, no tagging

- [ ] `uv build --wheel`; confirm the wheel contains both modules.
- [ ] `uvx --from <local path> superhumandoc-mcp` starts and exits cleanly.
- [ ] Drive the installed console script as a **real stdio subprocess** and
      confirm `initialize()` and `list_tools()` succeed against it, returning
      zero tools. This is the one check that exercises the console script, the
      entry point, `run()`'s transport argument, and the wheel together.
- [ ] Confirm classic `httpx` is absent from `uv.lock`.

## Done when

`uvx` runs the console script from a local build, a real stdio client completes
`initialize()` and sees zero tools, and the in-process test suite passes.

At that point RFC 0007 is shippable, but **the Accepted → Implemented transition
is a separate step** requiring the owner: it needs the shipping commit SHAs in
`commits:`, Implementation notes written, and `git mv` into
`_rfc/archive/implemented/`. Whether Implemented can be claimed at all without a
pushed tag is a judgement for the owner, since RFC 0007's Distribution section
describes installing from a git tag and that will not have been exercised
against a real remote.
