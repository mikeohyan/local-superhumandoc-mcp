- [x] **Step 3: Implement validation**

The plan's code was corrected during implementation. The original approach fetched the default inline, which would fail silently on a blank value (stripping it to empty, then uppercasing to empty). The shipped implementation first fetches the raw value, strips and uppercases it, then uses `or "INFO"` to supply the default only if the result is empty. This handles a blank value correctly without requiring extra error handling.

In `src/superhumandoc_mcp/config.py`, the shipped code uses:

```python
_LEVELS = ("CRITICAL", "ERROR", "WARNING", "INFO", "DEBUG")
```

and in `load_config`, just before the `return Config(` statement:

```python
    raw_log_level = resolved.get("SHDOC_LOG_LEVEL", "")
    log_level = raw_log_level.strip().upper() or "INFO"
    if log_level not in _LEVELS:
        raise ConfigError(
            f"SHDOC_LOG_LEVEL is {raw_log_level!r}, which is not a level. "
            f"Use one of: {', '.join(_LEVELS)}."

```

Note that the error message quotes the *raw* value (before normalization), so the user sees exactly what they typed.

```python
import logging
import sys
from pathlib import Path

import pytest

from superhumandoc_mcp.__main__ import _configure_logging
from superhumandoc_mcp.config import Config


def _config(level: str) -> Config:
    return Config(
        api_key="k",
        doc_id="d",
        allow_destructive=False,
        log_level=level,
        env_file=Path("/nowhere/.env"),
        sources={},
    )


def test_configure_logging_applies_the_resolved_level():
    _configure_logging(_config("DEBUG"))
    assert logging.getLogger().level == logging.DEBUG


def test_configure_logging_can_lower_the_level_again():
    _configure_logging(_config("DEBUG"))
    _configure_logging(_config("WARNING"))
    assert logging.getLogger().level == logging.WARNING


def test_configure_logging_never_writes_to_stdout():
    _configure_logging(_config("INFO"))
    streams = [
        handler.stream
        for handler in logging.getLogger().handlers
        if isinstance(handler, logging.StreamHandler)
    ]
    assert streams, "expected basicConfig to install a handler"
    assert sys.stdout not in streams
```

Assert by identity rather than by `stream.name`: under pytest's capture,
`sys.stderr` is replaced by an object that need not carry a `name`, so a
name comparison would fail for reasons unrelated to the code. Identity
against `sys.stdout` is what actually matters — stdout carries the MCP
transport, and a log line written there corrupts it.

Add a fixture at the top of the file so these tests cannot leak logging
state into the rest of the suite:

```python
@pytest.fixture(autouse=True)
def _restore_root_logger():
    root = logging.getLogger()
    saved_level, saved_handlers = root.level, root.handlers[:]
    yield
    root.handlers[:] = saved_handlers
    root.setLevel(saved_level)
```

The second test is the reason `force=True` is needed below: `logging.basicConfig` is a no-op once the root logger has handlers, so without it a second call silently does nothing and the level would depend on test ordering.

- [x] **Step 7: Implement the wiring**

The plan's approach of using `logging.basicConfig` on root was corrected during implementation. The original approach would configure the root logger, which would cascade to every library's logging too — `httpx`, for example, would emit a line per API call for users who never asked for that. The shipped implementation configures only the `superhumandoc_mcp` logger with `propagate = False`, so dependency logging is not affected.

In `src/superhumandoc_mcp/__main__.py`, the shipped code adds `import logging` and uses:

```python
def _configure_logging(config: Config) -> None:
    """Apply the resolved level to this package's own logger, not the root.

    stderr, not stdout: stdout carries the MCP transport. Scoped to the
    `superhumandoc_mcp` logger, rather than `logging.basicConfig` on root,
    because raising root's level switches on every library's own logging too
    -- `httpx`, for one, would start emitting a line per API call for a user
    who never asked for that. `propagate = False` keeps those same records
    from reaching root's handlers a second time. The logger's handlers are
    replaced outright, not appended to, so a second call (or a repeated
    lowering of the level) does not accumulate duplicate output.
    """
    handler = logging.StreamHandler(sys.stderr)
    handler.setFormatter(logging.Formatter("%(levelname)s %(name)s: %(message)s"))

    logger = logging.getLogger("superhumandoc_mcp")
    logger.handlers = [handler]
    logger.setLevel(config.log_level)
    logger.propagate = False
```

Then call it in `main`, immediately after the `load_config` try/except block and before `_identify` runs, so that anything this package logs during identification obeys the configured level:

```python
    _configure_logging(config)
```

### Task 5: Record what uv actually does with a git ref

The `packaging` topic states that "uv caches on the fully-resolved commit hash, so a branch pin does not pick up new commits without `--refresh`," and concludes a branch pin is quietly stale. On uv 0.11.6 that is not what happens. Validation observed the opposite: adding a commit to a scratch clone's `main` and reinstalling `@main` **without** `--refresh` picked up the new commit immediately, and force-moving a tag and reinstalling `@v0.1.0` picked up the moved commit immediately. What is cached by commit hash is the built distribution; the ref-to-commit resolution appears to happen fresh each time.

This does not change the decision. "Pin tags, never branches" and "never move a published tag" both survive — and the second is now better supported, because moving a tag is observed to actually change what consumers get. Only the stated reasoning is wrong.

That RFC is Implemented and its body is frozen, so this correction goes to `docs/validation/` as evidence. Nothing in `docs/` is authoritative for a decision; this file records a fact, and the decision it bears on is unchanged.
