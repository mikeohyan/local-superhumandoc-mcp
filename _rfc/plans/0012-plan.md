# Export subsystem implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the export half of RFC 0012 — kickoff, poll loop, download,
concurrency — and land `read_page`, the last tool RFC 0013 enumerates.

**Architecture:** A page export is three hops on two different hosts. A `POST`
to the API starts it and returns an id; a status `GET` polled on the API returns
a signed download link; a plain `GET` to S3, with no bearer token and outside
every rate bucket, fetches the body. The first two reuse the existing client and
its throttle. The third needs a second, tokenless client, because `DocsClient`
attaches `Authorization` unconditionally and acquires a bucket on every request.
Above all of it sits a concurrency layer: exports of one page must be
serialised, because the blob they contend for is keyed by page and document
rather than by request id.

**Tech Stack:** Python 3.11+, `uv`, `httpx2` (not classic `httpx`), `mcp` 2.x,
pytest with `asyncio_mode = "auto"`, tested against `httpx2.MockTransport` and
hand-written fakes. No new runtime dependencies.

**Spec:** `_rfc/0012-async-operation-polling-and-export-budget.md` rules 6–10,
and `_rfc/0013-html-content-and-the-read-write-cycle.md`'s `read_page` entry.
Both are Accepted and frozen. Operating values live in
`docs/reference/api-operational-constants.md` §1.4 and may be tuned there
without superseding, which rule 10 states in terms.

## Decisions this wave assumes

Each is already decided; none is open for re-litigation inside a task.

1. **A poll is not a retry.** Each status `GET` is an idempotent read the
   transport classifies as usual; the loop around them is this wave's subject.
   Nothing here weakens the replay rules.
2. **Both async operations share one loop shape** — wait, poll on a backing-off
   interval, stop on a terminal answer or a deadline. Mutation and export differ
   in their constants and in what counts as terminal, not in structure.
3. **A status 404 is "not yet" inside the grace window and terminal outside it.**
   No 404 has ever been observed from either status endpoint, across probes P4,
   P5 and P8. The window bounds patience rather than tracking a measured lag.
4. **410 Gone is terminal immediately.** Unlike a 404 it is unambiguous: the
   resource existed and is gone, so further polling cannot produce it.
5. **Exports of one page are serialised; exports overall are capped at three.**
   The blob key is `DOC_EXPORT_RENDERING/{pageId}/{docId}`, keyed by page and
   document and *not* by request id, so this is a correctness constraint rather
   than politeness.
6. **The export `POST` is charged to the write bucket.** A placeholder with an
   owner. P6 excluded the doc-content rates without identifying what applies;
   this is the conservative reading of what survives.
7. **The download is a separate hop** on another host, with no bearer token,
   outside every bucket, and its link is never cached — it expires in about five
   minutes while the file behind it lives for days.
8. **Bulk and recursive export are out of scope.** `read_page` reads one page.
   `EXPORT_MAX_PAGES_PER_CALL` was retired rather than owned.

## What E1 measured, and what it changes

Probe E1 ran on 2026-09-07, three exports against the scratch document. It is
the first measurement of export duration of any kind; every number in §1.4 was
previously reasoning from staff prose about other people's documents.

| Run | Page | Format | Kickoff | Polling | Download | Total |
|---|---|---|---|---|---|---|
| 1 | three paragraphs | markdown | 0.3 s | 2.6 s, 2 polls | 0.2 s | **3.1 s** |
| 2 | TORTURE-MD | markdown | 1.6 s | 4.8 s, 3 polls | 0.2 s | **6.6 s** |
| 3 | TORTURE-MD | html | 0.2 s | 2.4 s, 2 polls | 0.2 s | **2.9 s** |

Three runs on two small pages is not a distribution and says nothing about a
large document under load. What it establishes is the order of magnitude, which
was previously unknown to within two orders — and that is enough to settle the
one question that could have stopped this wave: a page read that runs an export
fits inside a single tool call with room to spare.

**It also removes a trap this plan would otherwise have had to work around.**
The recorded worry was that a dead link must be told from a good body by its
gzip magic bytes, and that httpx2 decodes `Content-Encoding` transparently for
`.content`/`.text`/`.json()`, so seeing `1f 8b` at all needs `iter_raw`. E1
shows the check never needs the raw stream: a good body is gzip-encoded and
decodes to markdown or HTML, and an error body is plain XML with **no**
`Content-Encoding` at all. Either way `.text` yields readable text. Task 4
checks the decoded text, not bytes — and checks the status code besides, which
the XML prefix alone would not.

`tests/conftest.py` already carries `FakeClock`, `_fixtures`, `_config`,

```python
class _Downloads:
    """Stands in for `downloads.Downloader`. Counts fetches, answers each URL
    from `bodies`, and raises DownloadUnusable for any URL in `dead` — which is
    how a stale link is spelled to the export loop. `dead_all` fails every URL,
    for the case where a link never comes good."""

    def __init__(self, bodies: dict[str, str] | None = None, *,
                 default: str = "", dead: set[str] | None = None,
                 dead_all: bool = False) -> None:
        self._bodies = bodies or {}
        self._default = default
        self._dead = dead or set()
        self._dead_all = dead_all
        self.calls = 0

    async def fetch(self, url: str, deadline) -> str:
        self.calls += 1
        if self._dead_all or url in self._dead:
            raise DownloadUnusable(url, "test double")
        return self._bodies.get(url, self._default)


def _fixed_downloader(body: str) -> _Downloads:
    return _Downloads(default=body)


def _counting_downloader(body: str) -> _Downloads:
    """The same object as `_fixed_downloader`, named for the tests that read
    `.calls`. Kept distinct so a cache test reads as being about the count."""
    return _Downloads(default=body)


def _downloader_failing_on(url: str, *, then: str) -> _Downloads:
    return _Downloads(default=then, dead={url})


def _always_failing_downloader() -> _Downloads:
    return _Downloads(dead_all=True)
```

### Task 3: The three API calls export needs

**Files:** Modify `src/superhumandoc_mcp/api.py`. Test: `tests/test_api.py`.

**Interfaces:** Produces
`await get_page(page, deadline) -> dict`,

Three facts govern the shapes, all recorded in
`docs/reference/api-operational-constants.md` and two confirmed live by probe
E1:

- The kickoff is `POST /docs/{docId}/pages/{page}/export` with body
  `{"outputFormat": "markdown"|"html"}` and answers **202** with
  `{"id", "status", "href"}` — **`id`, not `requestId`**. E1 confirmed this

  this is the endpoint it breaks on.

  page-scoped, unlike `/mutationStatus/{requestId}`, which is document-agnostic

  `/mutationStatus/` will not accept it.
- `get_page` exists for `read_page`'s two preconditions: `contentType` decides
  whether the page can be exported at all, and `updatedAt` is half the key a
  rendered page is cached under.

### Task 4: The download hop, and telling a body from an error

**Files:** Create `src/superhumandoc_mcp/downloads.py`. Modify
`src/superhumandoc_mcp/errors.py` — one new exception there, nothing else.
Test: `tests/test_downloads.py`.

**Interfaces:** Produces `Downloader(transport=None)` with
`await fetch(url, deadline) -> str`, raising `DownloadUnusable` (a new
`ClientError` subclass) when the response is not usable page content.

This is the only place in the client that talks to a host other than the API,
and it shares none of `client.py`'s policy. It must **not** send the bearer
token: the URL is pre-signed, the host is Amazon's, and a credential sent to a
third party has left the process. It must not acquire a rate-limit bucket
either — the buckets are the API's, and this request never reaches the API.

**It takes a deadline**, and derives its request timeout from
`deadline.remaining_with_tail()`. `deadline.py` reserves that tail for exactly
this case, the terminal fetch of a result already paid for. A download with no
timeout can pin a global concurrency slot forever, and three of those wedge
every later `read_page` — see Task 6.

**Three things make a response unusable, not one.** An earlier draft checked
only for an XML prefix, which would have let a 500 with a plaintext body, or an
error page from something sitting in front of the bucket, through as "the page":

1. **A non-2xx status**, whatever the body says.
2. **An S3 error document** — text whose first non-space characters are `<?xml`
   *and* which carries an `<Error` element, or which begins with `<Error`
   outright. Requiring the element rather than the prefix alone matters because
   XHTML may legitimately open with an XML declaration, and an HTML export that
   did so would otherwise become permanently unreadable and be reported as a
   link problem — sending the reader to look at the wrong thing.
3. Nothing else. **An empty body is content**, not an error: a blank canvas page
   exports to nothing, and refusing it would make an empty page unreadable
   without saying why.

### Task 5: The export poll loop and the re-mint counter

**Files:** Create `src/superhumandoc_mcp/export.py`. Test:
`tests/test_export.py`.

**Interfaces:** Consumes `DocsApi.begin_export`, `DocsApi.get_export_status`,
`Downloader.fetch`, `Deadline.clamp`, `UpstreamRefused.status`. Produces
`await export_page(api, downloader, page, output_format, deadline, *, clock,
sleep) -> str`.

The loop is `polling.py`'s shape with export's constants and export's terminal
conditions. **Read `polling.py` before writing this** — the same mistakes are
available here, and two of them bit that module: an unassigned grace-window
variable, and an opening sleep that runs before any loop condition and so
overshoots into the reserved tail. Assign the grace window's end before the
loop, unconditionally, and clamp the opening sleep.

What differs from the mutation loop:

- **The terminal signal is `downloadLink` or `error`, never `status`.** E1 saw
  `status` present and accurate in all three runs, flipping to `complete` on
  exactly the poll that first carried a link — but the field is absent from the
  schema and no error path has been observed to populate it. Log it if you like;
  do not branch on it.
- **410 is terminal at once**, with no grace window. It is declared on this
  endpoint and means the resource existed and is gone.
- **404 keeps its grace window**, `EXPORT_404_GRACE_S`.
- **A link that fails its body check is re-minted**, up to
  `EXPORT_MAX_LINK_REFRESH` times, by **re-entering the same poll loop** rather
  than by running a second ladder beside it. This is load-bearing: a separate
  ladder would not get the 404 grace window the loop grants, so a moment's
  replication lag during a re-mint would fail an export that patience would have
  completed — and it would be charged against the tool-call deadline rather than
  the export ceiling Task 1 just tuned. One loop, one ceiling, a counter for the
  re-mints. The specification sanctions the re-mint itself: *"Call this method
  again to get a fresh link."* A link expires in five minutes while the file
  lives for days, so a stale link is the likeliest cause of a late failure.
- **A kickoff carrying no `id` fails immediately, naming that.** `.get("id")`
  returning `None` would otherwise be polled as the literal path segment
  `"None"`, answer 404, burn the entire twenty-second grace window, and report
  replication lag — failing slowly and for the wrong stated reason.

class _ExportApi:
    """Returns each queued status reply in turn; a reply that is an exception
    is raised rather than returned, so a test can queue a 404 or a 410. An
    exhausted queue answers `{}`, which is non-terminal -- an export that never
    completes."""

    def __init__(self, replies, *, kickoff=None):
        self._replies = list(replies)
        self._kickoff = kickoff if kickoff is not None else {"id": "exp-1"}
        self.begun = 0

    async def begin_export(self, page, output_format, deadline):
        self.begun += 1
        return self._kickoff

    async def get_export_status(self, page, request_id, deadline):
        reply = self._replies.pop(0) if self._replies else {}
        if isinstance(reply, Exception):
            raise reply
        return reply

### Task 6: Serialising exports of one page

**Files:** Create `src/superhumandoc_mcp/gate.py`. Test: `tests/test_gate.py`.

**Interfaces:** Produces `ExportGate` with
`async with gate.for_page(page_id, deadline): ...`.

The first concurrency primitive in this codebase. Two limits compose: one
in-flight export per page, and at most `EXPORT_CONCURRENCY_GLOBAL` overall. The
per-page limit is a **correctness** constraint — the blob is keyed by page and
document, not by request id, so two concurrent exports of one page contend for a
single object. The global cap is a judgement about how much traffic to generate.

Acquire the global semaphore **before** the per-page lock, consistently, and say
why in a comment: a fixed order is what keeps two orderings from deadlocking
each other. Since `for_page` is the only path to either, no caller can invert it.

**The wait is bounded by the deadline.** Wrap the acquisition in
`asyncio.wait_for(..., timeout=deadline.remaining())` and raise a `ClientError`
naming the wait when it expires. Without this, queueing for a slot is time the
deadline can measure but nothing can act on: a call already out of budget still
waits, and a caller that spent its whole budget queueing reports a timeout
without ever saying it never got a slot. It also bounds the damage from a stuck
export — with three slots and no timeout anywhere, three wedged calls block every
later `read_page` for the life of the process.

The per-page lock dict is not evicted. This server is scoped to one document, so
it plateaus at that document's page count. Do not add eviction: removing a lock
while a task is about to acquire it is a race, and the growth it would prevent is
bounded already.

async def test_two_exports_of_one_page_do_not_overlap():
    """The blob they would write is keyed by page and document, not by request
    id, so overlapping exports of one page contend for a single object. This is
    correctness, not pacing."""
    gate, overlap = ExportGate(), _OverlapCounter()

    async def one():
        async with gate.for_page("page-x", Deadline()):
            await overlap.hold()

    await asyncio.gather(one(), one(), one())
    assert overlap.max_concurrent == 1


async def test_exports_of_different_pages_do_overlap():

    multi-page read needlessly serial."""

    async def one(page):
        async with gate.for_page(page, Deadline()):
            await overlap.hold()

    await asyncio.gather(one("a"), one("b"))

### Task 7: `read_page`

**Files:** Modify `src/superhumandoc_mcp/tools/reads.py`. Test:
`tests/test_tools_reads.py`, `tests/test_server.py`, and
`tests/test_tools_writes.py` — Step 4 deletes a test that lives there.

**Interfaces:** Consumes `export_page`, `ExportGate`, `DocsApi.get_page`.
Produces
`await read_page(api, downloader, gate, cache, page_id_or_name, *, clock, sleep) -> dict`
and its registration.

**`clock` and `sleep` are parameters, and this is not optional.** Every other
tool function in this module and in `tools/writes.py` takes them, defaulting to
`time.monotonic` and `asyncio.sleep`, and threads them down. Without them, every
test that drives an export sleeps `EXPORT_INITIAL_SLEEP_S` on the real clock —
exactly the regression the previous wave shipped and the Global Constraints call
out by name.

The `tool-surface` topic specifies this tool exactly. It returns the page as
**HTML**. It requires `contentType == "canvas"` and refuses embed and sync pages
**with that reason** — the content type is readable in advance, so the refusal is
predictable rather than something discovered by trying.

**The cache is keyed on `(page_id, updatedAt)`, both parts.** Keyed on the
timestamp alone — a fair reading of "cached against `updatedAt`" — two pages
sharing a timestamp would serve each other's rendered HTML, which is plausible
after a bulk edit or a duplicated template and is silent wrong-page content. A
missing or null `updatedAt` means do not cache: serving a render that cannot be
invalidated is worse than paying for the export.

Its description must state that it is a projection in which images, tables,
buttons, controls, callouts and dividers may be missing or flattened; that it
must not be treated as the document; and that its output must not be sent back
as write content. That last clause is the only enforcement the
read-never-a-write-source rule has on the read side.

## What this wave still does not build

- **Bulk or recursive page export.** Out of scope by decision, not by omission.
  If a bulk read is ever wanted it is a `tool-surface` question first and a
  budget question second.
- **A measured export bucket.** `BUCKET_WRITE` remains the conservative reading
  of what probe P6 left standing. Settling it means provoking a 429, which this
  project does not do.
- **Markdown output from `read_page`.** The tool returns HTML. The export
  supports both, and the two differ on export — markdown drops page-level
  attachments, HTML retains them — but the decided surface names one format.
- **A test that a gzip-encoded body is decompressed.** Every download test builds
  its response through `MockTransport`, which hands back decoded text regardless
  of the client's decompression setting, so none of them exercises a real encoded
  stream. httpx2 decompresses by default and nothing here disables it; a
  regression would have to come from someone turning it off deliberately.
